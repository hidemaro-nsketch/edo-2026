# セグメンテーションデータ仕様書

このドキュメントでは、Voronoi ビジュアライゼーションに必要なセグメンテーションデータのフォーマットを定義します。

---

## 概要

システムは以下の2種類のデータを必要とします：

1. **アトラス画像** — セグメントを1枚の大きな画像にまとめたもの（テクスチャアトラス）
2. **マニフェストJSON** — 各セグメントの位置・カテゴリ・メタデータを記述したファイル

```
public/sakura/
├── atlas/
│   ├── sakura_atlas_0.png    ← アトラス画像（ページ0）
│   └── sakura_atlas_1.png    ← アトラス画像（ページ1、必要な場合）
└── segments.manifest.json     ← マニフェスト
```

---

## 1. 入力データ（セグメンテーション作業で用意するもの）

### 1-1. セグメント画像

各セグメント（花、葉、幹など）を個別のPNG画像として用意してください。

| 項目 | 仕様 |
|------|------|
| フォーマット | PNG（RGBA、32bit） |
| 背景 | **透明**（アルファ=0） |
| サイズ | 長辺 256〜384px 推奨（幹は最大512pxまで可） |
| トリミング | セグメント部分のみ（周囲の余白は除去）を推奨 |
| 色空間 | sRGB |

#### ファイル命名規則（推奨）

```
{ソース画像ID}_{カテゴリ}.png
```

例：
```
sakura_01_flower.png
sakura_01_leaf.png
sakura_01_trunk.png
sakura_02_flower.png
sakura_02_leaf.png
...
```

### 1-2. セグメントごとのメタデータ

各セグメントについて、以下の情報が必要です：

| フィールド | 型 | 説明 | 例 |
|-----------|-----|------|-----|
| `sourceImageId` | 文字列 | 元の桜画像を識別するID | `"sakura_01"` |
| `category` | 文字列 | セグメントの部位カテゴリ | `"flower"`, `"leaf"`, `"trunk"` |
| `trimmedSize` | [幅, 高さ] | トリミング後のセグメント画像サイズ（px） | `[256, 320]` |
| `bboxInSource` | [x, y, 幅, 高さ] | 元画像内でのバウンディングボックス（px） | `[122, 80, 256, 320]` |
| `originalSize` | [幅, 高さ] | 元画像のサイズ（px） | `[1024, 1024]` |
| `pivot` | [x, y] | 正規化されたピボット点（0〜1） | `[0.5, 0.5]` |

> **pivot**: セグメントの「中心」となる点。通常は `[0.5, 0.5]`（画像の中央）で問題ありません。特定の位置を中心にしたい場合に調整してください。

> **bboxInSource**: 元の桜画像のどの位置からこのセグメントが切り出されたか。元画像の空間的位置関係を再現する場合に使います。不要な場合は `[0, 0, trimmedSize[0], trimmedSize[1]]` としてください。

### 1-3. メタデータの提供方法

メタデータは以下のいずれかの形式で提供できます：

#### 方法A: CSVファイル

```csv
filename,sourceImageId,category,width,height,bbox_x,bbox_y,bbox_w,bbox_h,orig_w,orig_h
sakura_01_flower.png,sakura_01,flower,256,320,122,80,256,320,1024,1024
sakura_01_leaf.png,sakura_01,leaf,200,180,50,400,200,180,1024,1024
sakura_01_trunk.png,sakura_01,trunk,100,450,462,300,100,450,1024,1024
```

#### 方法B: JSONファイル

```json
[
  {
    "filename": "sakura_01_flower.png",
    "sourceImageId": "sakura_01",
    "category": "flower",
    "trimmedSize": [256, 320],
    "bboxInSource": [122, 80, 256, 320],
    "originalSize": [1024, 1024],
    "pivot": [0.5, 0.5]
  }
]
```

#### 方法C: ディレクトリ構造による暗黙的メタデータ

```
segments/
├── sakura_01/
│   ├── flower.png
│   ├── leaf.png
│   └── trunk.png
├── sakura_02/
│   ├── flower.png
│   └── leaf.png
...
```

この場合、フォルダ名が `sourceImageId`、ファイル名が `category` として解釈されます。

## 2. アトラス画像

アトラスパッカースクリプトが、入力セグメント画像を自動的にアトラスにまとめます。手動で作成する必要はありません。

### 仕様

| 項目 | 仕様 |
|------|------|
| フォーマット | PNG（RGBA）※将来的にKTX2へ移行可 |
| サイズ | 2048 × 2048 px（1ページあたり） |
| ページ数 | セグメント数に応じて自動決定（通常1〜3ページ） |
| パディング | セグメント間に8pxのパディング |
| アルファ | プリマルチプライド推奨 |

### GPU メモリ見積もり

| ページ数 | GPU メモリ |
|---------|-----------|
| 1ページ | 約 16 MB |
| 2ページ | 約 32 MB |
| 3ページ | 約 48 MB |

---

## 3. マニフェストJSON（出力）

アトラスパッカーが自動生成するファイルです。手動で作成する必要はありませんが、フォーマットを理解しておくとデバッグに役立ちます。

### 完全なスキーマ

```json
{
  "version": 1,
  "atlas": {
    "pages": [
      {
        "id": 0,
        "file": "sakura_atlas_0.png",
        "width": 2048,
        "height": 2048
      }
    ],
    "colorSpace": "srgb",
    "premultipliedAlpha": true,
    "paddingPx": 8
  },
  "categories": [
    { "id": 0, "name": "flower", "bit": 1 },
    { "id": 1, "name": "leaf",   "bit": 2 },
    { "id": 2, "name": "trunk",  "bit": 4 }
  ],
  "segments": [
    {
      "id": 0,
      "sourceImageId": "sakura_01",
      "categoryId": 0,
      "categoryMask": 1,
      "atlasPage": 0,
      "uvRect": [0.0, 0.0, 0.125, 0.156],
      "pixelRect": [0, 0, 256, 320],
      "trimmedSize": [256, 320],
      "originalSize": [1024, 1024],
      "pivot": [0.5, 0.5],
      "bboxInSource": [122, 80, 256, 320]
    }
  ]
}
```

### フィールド説明

#### `atlas`（アトラス情報）

| フィールド | 説明 |
|-----------|------|
| `pages[].id` | ページ番号（0始まり） |
| `pages[].file` | アトラス画像ファイル名 |
| `pages[].width/height` | アトラスのサイズ（px） |
| `colorSpace` | 色空間（常に `"srgb"`） |
| `premultipliedAlpha` | プリマルチプライドアルファか |
| `paddingPx` | セグメント間のパディング（px） |

#### `categories`（カテゴリ定義）

| フィールド | 説明 |
|-----------|------|
| `id` | カテゴリID（0始まり） |
| `name` | カテゴリ名（UIに表示される） |
| `bit` | ビットマスク値（フィルタリング用、2のべき乗） |

カテゴリは自由に追加可能です。ビットマスクは2のべき乗で割り当ててください：

```
flower = 1  (2^0)
leaf   = 2  (2^1)
trunk  = 4  (2^2)
branch = 8  (2^3)
bud    = 16 (2^4)
...
```

#### `segments`（セグメント情報）

| フィールド | 説明 |
|-----------|------|
| `id` | セグメントの一意ID（0始まり） |
| `sourceImageId` | 元の桜画像ID |
| `categoryId` | カテゴリID（`categories` の `id` に対応） |
| `categoryMask` | カテゴリのビットマスク値 |
| `atlasPage` | このセグメントが配置されたアトラスページ番号 |
| `uvRect` | `[u0, v0, du, dv]` — アトラス内のUV座標（正規化、0〜1） |
| `pixelRect` | `[x, y, width, height]` — アトラス内のピクセル座標 |
| `trimmedSize` | `[width, height]` — セグメント画像のサイズ（px） |
| `originalSize` | `[width, height]` — 元画像のサイズ（px） |
| `pivot` | `[x, y]` — ピボット点（正規化、0〜1） |
| `bboxInSource` | `[x, y, width, height]` — 元画像内のバウンディングボックス |

## 4. ワークフロー

```
1. 桜の写真をAIセグメンテーション
   → 花、葉、幹などの部位マスクを取得

2. マスクを使って各部位を切り出し、個別PNGとして保存
   → sakura_01_flower.png, sakura_01_leaf.png, ...

3. メタデータを用意（CSV, JSON, またはディレクトリ構造）

4. アトラスパッカーを実行
   → python scripts/pack_atlas.py --input segments/ --output public/sakura/
   → アトラス画像 + manifest.json が生成される

5. ブラウザで確認
   → pnpm dev
   → Voronoiセルにセグメント画像が表示される
   → UIボタンで花/葉/幹の表示切り替え
```

## 5. 想定規模

| 項目 | 推奨範囲 |
|------|---------|
| 桜画像の枚数 | 10〜30枚 |
| 1枚あたりのセグメント数 | 3〜5個 |
| 総セグメント数 | 30〜150個 |
| セグメント画像サイズ | 256〜384px（長辺） |
| アトラスページ数 | 1〜3ページ |

## 6. よくある質問

### Q: セグメントの形は四角形でなくていい？
はい。PNG のアルファチャンネルで透明部分を指定するので、どんな形でも対応できます。花びらの形、葉の形など、自然な形のままで問題ありません。

### Q: 同じカテゴリに複数のセグメントがあっていい？
はい。例えば1枚の桜画像から「大きな花」「小さな花」「つぼみ」のように複数の花セグメントを切り出せます。すべて `category: "flower"` として扱われます。

### Q: 新しいカテゴリ（枝、つぼみなど）を追加できる？
はい。`categories` 配列に新しいエントリを追加し、次の2のべき乗のビット値を割り当ててください。UIにも自動的にトグルボタンが追加されます。

### Q: 画像サイズがバラバラでも大丈夫？
はい。アトラスパッカーが自動的に配置を最適化します。ただし、長辺384pxを大きく超えるとアトラスページが増えるため、事前にリサイズすることを推奨します。

### Q: 元画像の位置関係は保存される？
`bboxInSource` フィールドに元画像内での位置を記録できます。現在の実装ではセル内でランダムに配置されますが、将来的にこの情報を使って元の空間配置を再現する拡張が可能です。
